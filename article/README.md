# 首发文章目录（article/）

本目录存放**白色封皮首发文章**的 Markdown 源文件与封面图片。文章阅读页与文章列表页**由生成脚本自动生成**，不手工编辑 HTML。

## 目录结构

```
article/
├── README.md            # 本文件（手工维护，生成脚本不覆盖）
├── article-NN.md        # 文章源文件（Markdown + front-matter 元数据）
├── covers/              # 封面 PNG（如 covers/article-01.png）
├── index.html           # 文章列表页（生成，勿手工编辑）
└── posts/               # 文章阅读页（生成，勿手工编辑；整个目录由脚本管理）
    └── <slug>.html      # 每篇文章一个页面，slug 来自元数据或文件名
```

- `article-01.md` 与 `article-02.md` 是**示例文章**（其中一篇带示例封面），用于演示整个流程，正式内容上线后可直接删除或替换；
- 生成产物（`index.html` 与 `posts/`）由脚本整体管理：脚本会覆盖 `index.html`、为每篇文章生成 `posts/<slug>.html`，并**删除上次生成、本次已不存在文章的旧页面**。请勿在 `posts/` 中放置其他文件。

## 新增一篇文章

1. 在 `article/` 下新建文件 `article-NN.md`（编号连续，如 `article-03.md`）；
2. 参考下面的模板填写 front-matter 与正文；
3. （可选）把封面 PNG 放入 `article/covers/`，并在 `cover` 字段里写相对路径；
4. 在仓库根目录运行生成命令：

```bash
python3 tools/build_articles.py
```

5. 把改动**连同生成出的 `article/index.html` 与 `article/posts/*.html` 一起提交**（本网站是纯静态托管，没有服务器端构建，生成产物必须入库）。

### 文章模板

````markdown
---
title: 文章标题
date: 2026-11-01
column: fiction
summary: 一句话摘要，显示在文章列表里。
cover: covers/article-03.png
---

# 第一节标题

正文段落。支持**加粗**、*斜体*、`行内代码`、[链接](https://example.com)与
![图片](images/插图.png)。

> 引用文字

- 列表条目

```python
print("代码块")
```
````

## 元数据字段

front-matter 是文件最开头的 `---` 与第二个 `---` 之间的部分，一行一个 `字段: 值`。

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 文章标题。缺失时**构建失败**。 |
| `date` | 是 | 发布日期，严格 `YYYY-MM-DD`（如 `2026-10-28`）。缺失或无效时**构建失败**。 |
| `column` | 是 | 栏目键（小写）：`fiction` 小说 / `poetry` 诗歌 / `essay` 散文 / `fanfic` 同人文学 / `short-poems` 特别专栏-短诗 / `others` 其他。缺失或未知值时**构建失败**。 |
| `summary` | 否 | 列表页摘要。缺失时自动取正文首段（并给出警告），建议显式填写。 |
| `cover` | 否 | 封面 PNG 相对 `article/` 的路径（如 `covers/article-03.png`）。缺失或无效时给出警告并降级为无图排版（见下）。 |
| `slug` | 否 | 页面文件名（小写字母、数字、连字符，≤64 字符）。缺失时默认用文件名主干（如 `article-03`）。重复时**构建失败**。 |

未知字段会给出警告并被忽略（用于发现拼写错误）。

## 错误与降级规则

**致命错误（脚本中止、退出码 1、不写任何文件）**：缺失 `title`；`date` 缺失/格式错误/不是有效日期；`column` 缺失或不在允许列表；`slug` 非法或重复；文件没有以 `---` front-matter 开头。修正后重新运行即可。

**警告（构建继续，优雅降级）**：

- 未指定 `cover`：文章页与所在栏目不显示题图，保持纯排版；
- `cover` 指向的文件不存在 / 不是 PNG 格式 / 不是以 `.png` 结尾：不使用题图，**不会生成破损图片**；
- 正文 `![图片](路径)` 指向的文件不存在或不是 `article/` 内的相对路径：改为文字占位「［图片缺失：…］」；
- 链接使用了 `javascript:` 等不安全协议：该链接按纯文本显示；
- 正文为空：页面只显示标题与摘要；
- 文件名不符合 `article-NN.md` 规则的 `.md` 文件：被忽略并警告（可当草稿保存，但不会发布）。

## 封面与栏目 Hero 题图规则

- `cover` 必须指向 **PNG** 文件（脚本会校验文件扩展名与 PNG 文件头签名），放在 `article/covers/` 下并写相对路径；
- 文章列表页中，每个**栏目的 Hero 题图 = 该栏目内最新一篇文章（按日期从新到旧，同日按文件名升序）中第一个有有效封面的文章的封面**。规则确定、可预测，不依赖文件系统遍历顺序；
- 某栏目没有任何有效封面时，该栏目不显示 Hero，降级为纯排版；
- 封面图在列表页按 `21:9`（移动端 `16:9`）响应式裁切展示，带 `alt` 文本与「封面来源」说明；图片懒加载，PNG 尺寸会写入 `width`/`height` 属性防止布局抖动。

## Markdown 支持范围

标题（`#` ～ `######`，页面内 `#` 映射为 h2，h1 留给文章标题）、段落、**加粗**、*斜体*、`行内代码`、`>` 引用、无序/有序列表（支持两空格缩进的一层嵌套）、`[链接](url)`、`![图片](路径)`、```` ``` ```` 围栏代码块（可带语言名）、`---` 分隔线。

**安全策略**：正文在渲染前整体做 HTML 转义，源文件中的任何原始 HTML 都按纯文本显示，不会被当作脚本执行；链接只允许 `http/https/mailto` 协议或站内相对路径；正文图片必须是 `article/` 内真实存在的相对路径。

## 排序规则

- 列表页栏目按首页顺序：小说 → 诗歌 → 散文 → 同人文学 → 特别专栏-短诗 → 其他（只显示有文章的栏目）；
- 栏目内文章按日期**从新到旧**；同日按文件名升序。新增多篇文章时排序稳定可预期。

## 运行与部署

```bash
# 生成（幂等：重复运行结果一致；会清理已删除文章的旧页面）
python3 tools/build_articles.py

# 自测（27 个用例，覆盖元数据错误、转义、封面降级、排序与清理）
python3 tools/test_articles.py
```

- 生成脚本**只依赖 Python 3 标准库**（macOS 自带 Python 3 即可），无需安装任何依赖；
- 生成页面是纯静态 HTML（不依赖运行时 JavaScript 读取 Markdown），部署到 GitHub Pages 等任意静态托管即可访问；
- 生成页面已包含与全站一致的 PWA `<head>` 区块与 Service Worker 注册：文章列表页用 `../` 前缀、文章页（二级目录）用 `../../` 前缀；
- **部署后记得递增 [sw.js](../sw.js) 顶部的 `CACHE_VERSION`**（全站缓存失效开关）。文章页面与封面按现有 Service Worker 策略缓存（导航网络优先、静态资源缓存优先），不加入预缓存清单。

## 常见问题

- **运行脚本报「构建中止」？** 按错误提示修正对应 `.md` 的元数据再重跑；中止时不会写入任何文件，已部署内容不受影响。
- **封面为什么没显示？** 检查 `cover` 路径是否相对 `article/`、文件是否真实存在、是否为合法 PNG；脚本输出中有对应的定位警告。
- **改了 Markdown 但页面上没变化？** 重新运行生成脚本并重新部署；如果通过 Service Worker 访问旧页面，确认已递增 `CACHE_VERSION`。
- **能直接双击打开生成页吗？** 可以：生成页是纯静态 HTML，不读取本地文件，file:// 下也能正常显示（PWA 功能除外）。
- **想留草稿？** 草稿文件改名为不符合 `article-NN.md` 的形式（如 `draft-xxx.md`）即会被忽略。
